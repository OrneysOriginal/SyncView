# Результаты проверки SyncWatch

Обновлено 3 октября 2026 года для **0.2.0-beta.1**. Первоначальная проверка коммита `930bfad` выявила восемь подтверждённых дефектов. В текущем коде они исправлены и проверяются обычными регрессионными тестами; ожидаемых падений `xfail` больше нет.

## Проверка текущего кода

Полный запуск: **75 passed**, без пропущенных или ожидаемо падающих тестов. Ruff и `git diff --check` пройдены. Окружение: Linux, Python 3.10.12, PySide6 6.11.2, websockets 15.0.1, pytest 8.4.2. Qt запускается в режиме `offscreen`, WebSocket-сценарии используют настоящие локальные сокеты.

| Исправление | Подтверждение |
| --- | --- |
| Выход закрывает комнату, сервер и соединения; порт можно использовать повторно | `test_go_home_closes_room`, `test_close_frees_port_and_new_room_has_new_identity` |
| Ведущий и ведомые ставят паузу на одной позиции | `test_pause_ends_at_same_position`, интеграционный сценарий трёх окон |
| Коррекция учитывает движение видео за время задержки | `test_correction_projects_playing_position` |
| Клиентские команды не изменяют воспроизведение ведущего | проверки GUI и настоящего сетевого соединения |
| Пакеты другой сессии не исполняются | `test_network_rejects_wrong_session`, `test_old_session_command_is_ignored` |
| Несколько ведомых получают рассылку и имеют отдельную готовность | проверки трёх соединений, всех флагов готовности и трёх окон |
| Отключение участника отражается в состоянии комнаты | сетевые и интеграционные проверки выхода |
| Повреждение в любой части передаваемого файла обнаруживается | регрессия повреждённого 8 МиБ файла и полный SHA-256 |

Дополнительно проверены адресная передача только выбранному получателю, подтверждение целостности, объявление ранее выбранного видео новому участнику, замена отложенной команды, игнорирование результата старой загрузки, отсутствие ложной готовности при ошибке декодера, безопасные имена Windows, параллельные временные файлы, отказ от перезаписи, отмена, изменение исходника и проверка размера до записи. Некорректные типы, бесконечные числа и неполные обязательные поля отклоняются до GUI.

Экран запуска проверен настоящим Qt: отзывчивость при подготовке, создание окна в GUI-потоке, отмена, ошибки и SystemExit при загрузке зависимости. Проверен двойной клик: полноэкранный переход не вызывает лишний одиночный клик.

## Границы готовности релиза

Полные GUI/сетевые тесты заменяют VLC управляемой моделью. Это подтверждает работу протокола, таймеров, состояния и файловой передачи, но не качество настоящего видео или аудиосинхронизации.

В сборщик включена проверка настоящего VLC через тестовый AVI: декодированные кадры, Play/Pause/Seek и код завершения. Она использует фиктивные выходы, поэтому не проверяет картинку, звук и поведение драйверов. Новый Windows-пакет и Windows workflow в этой сессии не выполнялись.

Полный запуск из исходников с настоящим libVLC 3.0.16 на Linux проверен через `--smoke-test`: декодирование AVI и Play/Pause/Seek прошли, код завершения 0. Для этого использованы библиотеки из временного окружения. Контроль проверяет декодированные кадры: фиктивный видеовыход не гарантирует счётчик отображённых кадров.

Версия подготовлена для **предварительного релиза** после успешной Windows-сборки. Перед стабильным релизом проверьте новый ZIP на чистой Windows 10/11 x64 без Python и VLC: MP4/MKV со звуком, ведущий и минимум два ведомых, смена файлов, отмена большой передачи, обрыв Wi-Fi и повторное создание комнаты. Протокол 2 требует обновления всех участников.

Остающиеся ограничения: доверенная локальная сеть без TLS, нет автоматического переподключения и возобновления передачи, нет подписи Windows/macOS, настоящий выпуск macOS не проверен. Синхронизация оценивает задержку; точность при асимметричной сети и нагрузке на декодер требует проверки на физических устройствах. Большая часть координации пока находится в MainWindow.
