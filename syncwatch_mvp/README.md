# SyncWatch

SyncWatch позволяет смотреть локальное видео в одной комнате: ведущий выбирает файл и управляет воспроизведением, несколько ведомых получают копию видео и команды Play/Pause/Seek по локальной сети.

Текущая версия — **0.2.0-beta.1**, протокол **3**. Всем участникам нужна новая сборка: пакеты с протоколами 1 и 2 несовместимы с подтверждением перемотки. Результаты проверки и границы готовности: [AUDIT.md](AUDIT.md). Инструкция выпуска: [BUILD.md](BUILD.md).

## Запуск на Windows

1. Скачайте `SyncWatch-Windows-x64.zip` из [Releases](https://github.com/OrneysOriginal/SyncView/releases).
2. Распакуйте архив целиком.
3. Запустите `SyncWatch.exe`. Папка `_internal` должна оставаться рядом.

В готовый пакет входят Python, Qt и VLC. Консоль не открывается. После загрузки Python и Qt появляется экран с этапами запуска; при ошибке показывается причина и путь к журналу. Старые архивы не обновляются автоматически — для новых возможностей нужна новая сборка.

## Совместный просмотр

1. Подключите компьютеры к одной локальной сети. На ведущем разрешите приложению входящие соединения в частной сети Windows.
2. На ведущем нажмите «Создать комнату». Передайте участникам IP, порт и шестизначный код комнаты.
3. На ведомых нажмите «Подключиться» и введите эти данные и имя устройства.
4. Ведущий выбирает видео и по очереди отправляет его каждому ведомому кнопкой «Отправить файл». Ведомые подтверждают получение. Ведущий может выбрать файл заранее: сведения автоматически отправляются новым участникам.
5. Дождитесь готовности всех участников и совпадения файлов. У ведущего отображается готовность каждого ведомого.
6. Ведущий запускает просмотр, ставит паузу и перематывает видео.

При подключении нового участника, смене видео или обрыве соединения просмотр приостанавливается. После подготовки продолжайте кнопкой Play. «Выйти из комнаты» закрывает соединения и отменяет отложенные команды; ведущий может создать новую комнату в том же процессе.

Ведомый не может выбрать, сменить или отправить файл, поставить общую паузу и перемотать видео. После смены видео ведущим готовность ведомых сбрасывается; новую копию нужно передать каждому участнику. Полученные файлы проверяются по размеру и SHA-256 всего содержимого. При различающейся оценке длительности ведущий может разрешить просмотр без совпадения.

## Передача видео

Ведущий выбирает получателя в списке рядом с «Отправить файл». Ведомый подтверждает предложение и принимает только выбранное видео ведущего; одновременно на одном устройстве выполняется одна передача.

Во время передачи управление просмотром блокируется. Получатель проверяет размер и полный SHA-256 и подтверждает результат отправителю. Копия сохраняется в `~/.syncwatch/received` и открывается в приложении. Существующие файлы не перезаписываются. Доступны отмена и таймаут ожидания; при обрыве временная копия удаляется. Возобновление прерванной передачи не реализовано.

## Управление

- Space или одиночный клик по видео: Play/Pause у ведущего.
- Кнопки «◀◀ 5» / «5 ▶▶», ←/→ и J/L: назад/вперёд на 5 секунд у ведущего. Повторные нажатия складываются: три нажатия дают 15 секунд. Поверх видео появляется индикатор направления и суммы шагов, в том числе у ведомых при выполнении команды.
- Нажатие на полосу времени или перетаскивание её ползунка: переход к выбранной позиции у ведущего. Перемотка сохраняет состояние воспроизведения или паузы.
- Двойной клик: полноэкранный режим; Esc: выход из него.
- Громкость и отключение звука действуют локально на каждом устройстве.

При перемотке во время просмотра приложение само делает короткую паузу: ведомые переходят к новой позиции и подтверждают её ведущему. После подтверждений от всех устройств, включая плеер ведущего, просмотр продолжается автоматически в назначенный общий момент. Дополнительно нажимать Pause или Play не нужно. Если видео уже было на паузе, оно остаётся на паузе.

Повторная перемотка заменяет предыдущую: учитываются подтверждения только последней позиции. Ожидание показано под видео, в том числе в полноэкранном режиме. Если подтверждение не приходит за 10 секунд или плеер сообщает ошибку, все остаются на паузе; ведущий может нажать Play для повторной синхронизации. Отключение участника и смена комнаты или видео отменяют ожидание и автоматическое продолжение.

## Исходники и проверка

Для Windows-сборки используйте Python 3.12 x64 и полный VLC x64. Зависимости закреплены в `requirements.txt`; инструменты проверки — в `requirements-dev.txt`, сборки — в `requirements-build.txt`. Python-код совместим с Python 3.10+, но выпускной пакет собирается на Python 3.12.

Из каталога `syncwatch_mvp`, в подготовленном окружении:

```bash
python -m src.main
python -m pytest -q
python -m ruff check src tests
```

Для запуска из исходников нужен доступный VLC runtime. На Windows его можно указать через `VLC_HOME`. Сборка двойным щелчком: `Build Windows.cmd`. На macOS предусмотрен отдельный сборочный скрипт; новый пакет macOS пока не проверен.

Тесты используют настоящий Qt и локальные WebSocket-соединения. В интеграционных тестах видеоплеер заменён управляемой моделью. `--smoke-test` дополнительно проверяет настоящее декодирование сгенерированного AVI и Play/Pause/Seek, без внешнего генератора видео; он использует фиктивные аудио- и видеовыходы и не проверяет картинку или звук на физическом устройстве.

## Сеть и данные

Порт ведущего по умолчанию — TCP 45892. Интернет для комнаты не нужен. Если показано несколько локальных IP, используйте адрес сетевого адаптера, общего с ведомыми. VPN и несколько адаптеров могут влиять на доступность комнаты.

Журнал: `%USERPROFILE%\.syncwatch\logs\syncwatch.log` на Windows, `~/.syncwatch/logs/syncwatch.log` на других системах. Журнал ротируется: до четырёх файлов по 2 МиБ. Полученные видео автоматически не удаляются.

Приложение рассчитано на доверенную локальную сеть: транспорт `ws://`, без TLS и автоматического переподключения. Не открывайте порт комнаты в интернет. Код комнаты и проверка роли защищают сценарий управления, но не заменяют шифрование и учётные записи.

## Выпуск

Windows-сборщик проверяет код и тесты, собирает приложение во временный каталог, запускает проверку готового пакета и только затем публикует папку и ZIP в `dist`. Ручной workflow **Build Windows application** выполняет эти шаги и по тегу `v0.2.0-beta.1` создаёт черновик предварительного релиза.

Перед обычным стабильным релизом нужна проверка MP4/MKV со звуком на нескольких Windows-компьютерах, включая чистую систему без Python и VLC. Подпись приложения и нотариальное заверение macOS в проекте не настроены.

Подробности реализации: [ARCHITECTURE.md](ARCHITECTURE.md). Правила распространения встроенных Python, Qt, libVLC и их модулей относятся к соответствующим сторонним компонентам; сохраняйте их уведомления и лицензии в пакете. Собственная лицензия исходников проекта пока не выбрана.
