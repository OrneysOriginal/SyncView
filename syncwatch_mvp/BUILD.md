# Автономная сборка SyncWatch

Конечному пользователю не нужны Python, VLC, PySide6 или другие программы. Они включаются в дистрибутив. Сборщик должен один раз подготовить VLC runtime и запустить соответствующий скрипт.

## Запуск на Windows без консоли

Готовый архив `SyncWatch-Windows-x64.zip` нужно полностью распаковать. Откройте `SyncWatch.exe` двойным щелчком. Консоль не появляется: в spec установлен `console=False`.

После загрузки Python и Qt появляется экран запуска с анимированным индикатором и этапами подготовки. Он остаётся отзывчивым во время загрузки компонентов и инициализации VLC, затем уступает место основному окну. Индикатор не показывает проценты: длительность подготовки заранее неизвестна. При ошибке экран скрывается и появляется сообщение с причиной и путём к журналу. Самая ранняя загрузка Python/Qt ещё выполняется без этого экрана.

Экран включается в сборку автоматически и не требует дополнительных файлов. Старые `.exe` и ZIP не обновляются сами: запустите `Build Windows.cmd` из обновлённых исходников или заново выполните Windows workflow и используйте новый архив.

Рядом с `.exe` должен остаться каталог `_internal` с Python, Qt, библиотеками и VLC. Можно создать ярлык на `.exe` и положить его на рабочий стол. Переносить только `.exe` из папки нельзя. Журнал ошибок находится в `%USERPROFILE%\.syncwatch\logs\syncwatch.log`.

### Получение архива через GitHub

В репозитории подготовлен ручной workflow `.github/workflows/build-windows.yml`. После размещения этих изменений в GitHub:

1. Откройте вкладку **Actions** → **Build Windows application**.
2. Нажмите **Run workflow** и выберите ветку с этими изменениями.
3. Дождитесь успешного завершения. Windows runner установит Python 3.12 x64, скачает официальный VLC 3.0.23 x64 и проверит контрольную сумму архива.
4. В разделе **Artifacts** скачайте `SyncWatch-Windows-x64`.
5. Распакуйте архив артефакта, затем находящийся внутри `SyncWatch-Windows-x64.zip`; запустите `SyncWatch.exe` из полученной папки.

Сборщик перед упаковкой проверяет код через Ruff и выполняет pytest. Затем `--smoke-test` запускает Qt, VLC и сетевой поток, создаёт небольшой AVI средствами Python и проверяет декодирование, Play/Pause/Seek. Фиктивные аудио- и видеовыходы позволяют выполнить проверку без звуковой карты; картинку, звук и синхронизацию физических устройств она не проверяет. Workflow пока не запускался в рамках этой сессии; готового Windows-бинарника в репозитории нет.

VLC берётся из [официального каталога VideoLAN](https://download.videolan.org/pub/videolan/vlc/3.0.23/win64/). Версия runtime закреплена для сборки; перед выпуском её следует обновить и повторить проверку пакета. Workflow запускается вручную. По умолчанию он создаёт только артефакт; при заполненном поле `release_tag` также создаёт черновик предварительного релиза.

### Размещение приложения в Releases

GitHub Releases позволяет оформить отдельную страницу версии с названием, описанием и архивом программы. Исходники остаются в Git, а готовое приложение прикрепляется к релизу. Пример страницы: [релизы SyncView](https://github.com/OrneysOriginal/SyncView/releases).

Чтобы получить релиз через подготовленный workflow, после отправки изменений на GitHub:

1. Откройте **Actions → Build Windows application → Run workflow**.
2. Выберите ветку с обновлённым сборщиком и в поле `release_tag` укажите `v0.2.0-beta.1`. Тег должен совпадать с версией в `src/version.py`.
3. Дождитесь успешного выполнения. Будет собран Windows-пакет, проверен его запуск, создан новый тег на собранном коммите и черновик релиза с прикреплённым `SyncWatch-Windows-x64.zip`.
4. Откройте **Releases**, найдите черновик, проверьте описание и нажмите **Publish release**. Перед публикацией можно проверить скачанный пакет на своём Windows.

Используйте новый тег для каждой версии: workflow не перезаписывает существующие теги и релизы. Если поле `release_tag` оставить пустым, получится обычная сборка в **Artifacts**. Нужные права записи получает только отдельная задача создания релиза, после успешной сборки. Локально проверены YAML и синтаксис команд; workflow создания релиза в этой сессии не запускался.

Если архив уже собран на вашем компьютере, загрузить его можно вручную:

1. Откройте **Releases → Draft a new release**.
2. Создайте тег версии, выберите ветку с соответствующими исходниками и укажите заголовок, например `SyncWatch v0.2.0-beta.1 — Windows x64`.
3. Добавьте описание запуска и перетащите `dist\SyncWatch-Windows-x64.zip` в поле прикрепления файлов.
4. Нажмите **Publish release**.

В **Assets** пользователи скачивают `SyncWatch-Windows-x64.zip` и распаковывают его целиком. Автоматические файлы **Source code (zip/tar.gz)** содержат исходники; для запуска готовой программы нужен прикреплённый Windows-пакет. Инструкция управления релизами: [GitHub Docs](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository).

### Сборка двойным щелчком на Windows

Если GitHub Actions недоступен, один раз установите Python 3.12 x64 с Python Launcher (`py`) и полный VLC x64. Затем откройте `Build Windows.cmd` двойным щелчком. Вручную вводить команды не нужно; окно с выводом видно только во время сборки. Интернет нужен для установки зависимостей.

Скрипт найдёт VLC в `C:\Program Files\VideoLAN\VLC`, создаст отдельное окружение `.venv-build`, установит зависимости и соберёт приложение. При успехе откроется папка `dist\SyncWatch` с готовым `.exe`, а архив появится в `dist\SyncWatch-Windows-x64.zip`. Дальнейший запуск приложения выполняется без консоли и без установленного Python/VLC на компьютере получателя.

Дождитесь сообщения `Created: ...SyncWatch-Windows-x64.zip` и автоматического открытия папки. Одного появления `.exe` недостаточно: в процессе работы PyInstaller файл может уже существовать, пока библиотеки ещё копируются. Обновлённый сборщик готовит пакет в `build\windows-package` и переносит его в `dist` после проверки запуска и создания архива. Если проверка не прошла, новая версия в `dist` не публикуется. Старая версия, оставшаяся после предыдущей сборки, при этом может по-прежнему находиться в `dist`.

Если VLC находится в другой папке, передайте путь через PowerShell по инструкции ниже. После изменения исходников выполните сборку заново.

## Почему сборки создаются отдельно

PyInstaller не выполняет кросс-компиляцию. Windows-пакет собирается на Windows, а `.app` — на macOS. Для Intel и Apple Silicon нужны VLC и Python той же архитектуры.

## Подготовка VLC runtime

Создайте каталог, содержащий полный runtime VLC, а не только одну библиотеку.

Windows:

```text
vlc-runtime/
├── libvlc.dll
├── libvlccore.dll
└── plugins/
```

Обычно эти файлы берутся из установленного или распакованного 64-битного VLC. Каталог можно удалить после сборки: его копия окажется внутри SyncWatch.

macOS:

```text
vlc-runtime/
├── lib/
│   ├── libvlc.dylib
│   └── ...зависимости...
└── plugins/
```

Подготовленный runtime должен соответствовать архитектуре сборки: `x86_64` для Intel или `arm64` для Apple Silicon.

## Windows x64

Откройте PowerShell в каталоге проекта:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\build_tools\build_windows.ps1 -VlcDir "C:\путь\к\vlc-runtime" -Clean
```

Результат:

```text
dist\SyncWatch-Windows-x64.zip
```

Пользователь распаковывает архив и запускает `SyncWatch.exe`. Устанавливать VLC или Python не нужно.

## macOS

```bash
./build_tools/build_macos.sh "/путь/к/vlc-runtime" --clean
```

Результат для текущей архитектуры:

```text
dist/SyncWatch-macOS-arm64.zip
# или
dist/SyncWatch-macOS-x86_64.zip
```

Для внутреннего тестирования неподписанное приложение открывается через контекстное меню **Открыть**. Для публичной раздачи необходимы подпись Developer ID и notarization.

## Ограничения проверки

Windows `.exe` собирается на Windows; в текущей Linux-сессии проверить готовый бинарник нельзя. Исправлена совместимость spec с PyInstaller 6 и добавлены проверки кодов возврата сборочных команд. Локальные тесты проверяют конфигурацию упаковки с заменой внешних компонентов. Правила `console=False`, упаковки в папку и сборки под целевую ОС описаны в [документации PyInstaller](https://pyinstaller.org/en/stable/operating-mode.html).

## Проверка автономности

Проверяйте пакет на чистой машине или виртуальной машине, где отсутствуют Python и VLC. После запуска проверьте открытие MP4/MKV, создание комнаты, подключение второго устройства, Play/Pause/Seek и отображение ping.

## Ошибка инициализации VLC

Ошибка `'NoneType' object has no attribute 'media_player_new'` означает, что `vlc.Instance()` вернул `None`, а старый код продолжил создание медиаплеера. Сам traceback не определяет, почему VLC отказал: возможны отсутствующие плагины, несовместимый комплект библиотек или ошибка поиска runtime.

В обновлённом коде Windows явно использует `libvlc.dll` и плагины из одного комплекта через `PYTHON_VLC_LIB_PATH`, `PYTHON_VLC_MODULE_PATH` и `VLC_PLUGIN_PATH`. Возможность отдельного выбора DLL в python-vlc подтверждается [исходным кодом библиотеки](https://github.com/oaubert/python-vlc/blob/master/generated/3.0/vlc.py). При отсутствии DLL или плагинов приложение выдаёт понятную ошибку; при отказе инициализации показывает выбранные пути и доступное сообщение VLC.

Проверьте, что архив распакован целиком и структура содержит:

```text
SyncWatch/
├── SyncWatch.exe
└── _internal/
    └── vlc/
        ├── libvlc.dll
        ├── libvlccore.dll
        └── plugins/
            └── ...каталоги с DLL плагинов...
```

Затем пересоберите **обновлённые исходники** через `Build Windows.cmd`; старый `.exe` от изменения исходников не обновляется. Скрипт теперь проверяет инициализацию VLC до упаковки, а затем старт собранного приложения, и создаёт архив только после успеха. Журнал содержит выбранный runtime и traceback; при ошибке сборки сохраните вывод окна и `%USERPROFILE%\.syncwatch\logs\syncwatch.log`.

## Важные замечания

- Не удаляйте каталог `vlc` из готового приложения.
- Windows Firewall может запросить разрешение на локальные входящие соединения — это системное разрешение, а не установка программы.
- Полный VLC runtime увеличивает размер архива, но обеспечивает поддержку кодеков без сторонней установки.
