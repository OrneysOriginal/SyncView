# SyncWatch

Техническое описание: [архитектура и протокол](ARCHITECTURE.md). Результаты проверки: [дефекты, тесты и план улучшений](AUDIT.md).

Документация описывает MVP. Сквозной просмотр на Windows/macOS и автономные сборки в текущем аудите не проверены. Есть подтверждённые ошибки паузы, коррекции и жизненного цикла комнаты; успешные unit-тесты не означают полной готовности.

Для запуска без консоли на Windows используйте `SyncWatch.exe`; получение сборки описано в [BUILD.md](BUILD.md). Сборку из исходников можно запустить двойным щелчком по `Build Windows.cmd`.

Для разработки используйте Python 3.12; зависимости теперь требуют `websockets>=14,<16`.

По требованию приложение должно поддерживать несколько ведомых. Текущая модель хранит один сокет и состояние одного участника; корректная рассылка нескольким ведомым пока требует доработки.

SyncWatch — настольное приложение для синхронного просмотра одного и того же локального видеофайла на двух компьютерах.

Один компьютер создаёт комнату и становится ведущим. Второй компьютер подключается к нему по локальной сети и становится ведомым. Для просмотра нужны локальные копии видео на обоих устройствах: их можно подготовить заранее или передать средствами приложения.

При обычном просмотре по сети передаются команды управления, позиции, сведения о файле и служебные сообщения. Также есть передача выбранного видеофайла второму участнику после его подтверждения: кнопка «Отправить файл». Полученная копия сохраняется в `~/.syncwatch/received` и открывается в приложении.

Приложение предназначено для работы между Windows и macOS без подключения к интернету.

# Как работает SyncWatch

Для совместного просмотра используются два компьютера в одной локальной сети.

Первый компьютер:

1. запускает SyncWatch;
2. создаёт комнату;
3. запускает локальный WebSocket-сервер;
4. показывает IP-адрес, порт и код комнаты;
5. становится ведущим устройством.

Второй компьютер:

1. запускает SyncWatch;
2. выбирает подключение к комнате;
3. вводит IP-адрес, порт и код комнаты;
4. подключается к ведущему;
5. становится ведомым устройством.

После подключения оба пользователя выбирают локальные копии одного видеофайла. Если копии у второго участника нет, первый может предложить передачу через «Отправить файл». Если файлы различаются, доступна кнопка «Продолжить без совпадения»; она не гарантирует совпадение сцен на временной шкале.

SyncWatch сравнивает:

- размер файлов;
- длительность;
- частичный SHA-256 отпечаток содержимого.

Если файлы совпадают, ведущему становится доступен запуск воспроизведения. Частичный отпечаток не доказывает равенство всех байтов файла.

Ведущий управляет:

- запуском;
- паузой;
- перемоткой;
- переходом к позиции;
- полноэкранным режимом на своём устройстве.

Ведомый автоматически выполняет команды ведущего.

Громкость регулируется локально на каждом компьютере и не синхронизируется.

# Основные возможности

SyncWatch поддерживает:

- создание комнаты в локальной сети;
- подключение по IP-адресу, порту и коду комнаты;
- работу без интернета;
- соединение Windows с Windows;
- соединение Windows с macOS;
- соединение macOS с macOS;
- синхронный запуск видео;
- синхронную паузу;
- синхронную перемотку;
- переход к выбранной позиции;
- проверку совпадения видеофайлов;
- отображение ping;
- отображение примерного рассинхрона;
- автоматическую коррекцию сильного рассинхрона;
- полноэкранный режим;
- управление воспроизведением кликом по видео;
- управление громкостью;
- отключение звука;
- автоматическое скрытие панели управления;
- управление горячими клавишами.

# Ограничения текущей версии

В текущей MVP-версии:

- поддерживается только два устройства;
- один компьютер является ведущим;
- второй компьютер является ведомым;
- управление воспроизведением доступно только ведущему;
- смена роли во время просмотра не поддерживается;
- видео передаётся только после подтверждения получателя; возобновление прерванной передачи отсутствует;
- на обоих компьютерах нужны локальные копии; их можно передать через приложение;
- соединение через интернет не поддерживается;
- соединение через разные локальные сети не поддерживается;
- работа через VPN не гарантируется;
- гостевые Wi-Fi-сети могут блокировать соединение между устройствами;
- музыкальная точность синхронизации аудиовыходов не гарантируется;
- для запуска из исходников требуется установленный VLC.

# Поддерживаемые платформы

## Windows

Поддерживаются:

- Windows 10 x64;
- Windows 11 x64.

Рекомендуется использовать:

- 64-битную версию Python;
- 64-битную версию VLC;
- стабильное подключение по Wi-Fi или Ethernet.

## macOS

Поддерживаются:

- macOS 13 и новее;
- Mac с процессором Intel;
- Mac с процессором Apple Silicon.

Версия Python и VLC должна соответствовать архитектуре компьютера.

Для Apple Silicon рекомендуется использовать нативные ARM64-версии Python и VLC.

# Требования перед запуском

Перед запуском убедитесь, что:

1. на компьютере установлен Python;
2. установлен VLC Media Player;
3. Python и VLC имеют одинаковую архитектуру;
4. проект распакован в отдельную папку;
5. оба компьютера подключены к одной локальной сети;
6. одинаковый видеофайл находится на обоих устройствах.

Рекомендуемые папки проекта:

Windows:

```text
D:\SyncWatch\syncwatch_mvp
```

или:

```text
C:\Projects\syncwatch_mvp
```

macOS:

```text
~/Projects/syncwatch_mvp
```

Не рекомендуется размещать проект в системных папках, где могут потребоваться права администратора.

# Развёртывание на Windows

## 1. Установите Python

Установите Python 3.12 x64.

Во время установки включите параметр:

```text
Add Python to PATH
```

После установки откройте PowerShell и проверьте версию:

```powershell
python --version
```

Ожидаемый результат:

```text
Python 3.12.x
```

Проверьте разрядность Python:

```powershell
python -c "import struct; print(struct.calcsize('P') * 8)"
```

Результат должен быть:

```text
64
```

Если команда `python` не работает, попробуйте:

```powershell
py --version
```

В таком случае в остальных командах можно использовать `py` вместо `python`.

---

## 2. Установите VLC Media Player

Необходимо установить полную 64-битную версию VLC.

После установки стандартный путь обычно выглядит так:

```text
C:\Program Files\VideoLAN\VLC
```

В папке должны находиться:

```text
libvlc.dll
libvlccore.dll
plugins\
```

Полные пути:

```text
C:\Program Files\VideoLAN\VLC\libvlc.dll
C:\Program Files\VideoLAN\VLC\libvlccore.dll
C:\Program Files\VideoLAN\VLC\plugins
```

Не рекомендуется использовать VLC из папки:

```text
C:\Program Files (x86)\VideoLAN\VLC
```

Эта папка обычно содержит 32-битную версию VLC, которая не будет работать с 64-битным Python.

## 6. Настройте VLC

В текущем окне PowerShell выполните:




Если команда выводит версию VLC без ошибки, библиотека подключена правильно.

# Как пользоваться приложением

## Подготовка устройств

Перед началом просмотра:

1. подключите оба компьютера к одной Wi-Fi-сети или одному Ethernet-маршрутизатору;
2. отключите VPN;
3. убедитесь, что сеть не является гостевой;
4. скопируйте одинаковый видеофайл на оба устройства;
5. запустите одинаковую версию SyncWatch;
6. убедитесь, что файл открывается в обычном VLC.

---

## Создание комнаты

На первом компьютере:

1. запустите SyncWatch;
2. нажмите «Создать комнату»;
3. дождитесь запуска сервера;
4. приложение покажет:
   - локальный IP-адрес;
   - порт;
   - код комнаты;
5. передайте эти данные пользователю второго компьютера.

Первый компьютер становится ведущим устройством.

---

## Подключение к комнате

На втором компьютере:

1. нажмите «Подключиться»;
2. введите IP-адрес ведущего;
3. введите порт;
4. введите код комнаты;
5. нажмите кнопку подключения.

После успешного соединения второй компьютер становится ведомым.

---

## Выбор файла

На каждом устройстве:

1. нажмите кнопку выбора видео;
2. выберите локальную копию файла;
3. дождитесь получения длительности;
4. дождитесь расчёта отпечатка;
5. дождитесь сообщения, что файлы совпадают.

Файлы считаются совпадающими, если:

- совпадает размер;
- длительность отличается не более чем на допустимый предел;
- совпадает частичный SHA-256 отпечаток.

Имя файла может отличаться, но содержимое должно быть одинаковым.

---

## Начало просмотра

После готовности обоих устройств ведущий может начать воспроизведение.

Управление выполняется только на ведущем устройстве.

Ведомое устройство автоматически получает и выполняет команды:

- Play;
- Pause;
- Seek;
- перемотка назад;
- перемотка вперёд.

Двойной щелчок:

```text
Включить или выключить полноэкранный режим
```

Движение мыши по плееру:

```text
Показать панель управления
```

Во время воспроизведения панель автоматически скрывается после нескольких секунд бездействия.

На паузе панель остаётся видимой.

В полноэкранном режиме вместе с панелью управления может скрываться курсор.

---

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| `Пробел` | Play/Pause |
| `←` | Перемотка назад на 5 секунд |
| `→` | Перемотка вперёд на 5 секунд |
| `J` | Перемотка назад на 10 секунд |
| `L` | Перемотка вперёд на 10 секунд |
| `Esc` | Выход из полноэкранного режима |

Горячие клавиши синхронной перемотки работают только на ведущем устройстве.

После перемотки сохраняется предыдущее состояние:

- если видео воспроизводилось, оно продолжит воспроизведение;
- если видео было на паузе, оно останется на паузе.

---

## Громкость

Громкость регулируется локально на каждом устройстве.

Изменение громкости на ведущем не влияет на громкость ведомого.

Это позволяет каждому пользователю выбрать комфортный уровень звука.

# Работа синхронизации

Ведущий отправляет команды с задержкой выполнения 350 мс. Ведомый отсчитывает её с момента получения, поэтому время доставки добавляется к его отставанию. Текущая реализация паузы и коррекции содержит ошибки расчёта позиции; подробности и воспроизводящие тесты приведены в [отчёте](AUDIT.md).

Ведомое устройство периодически отправляет ведущему:

- текущую позицию;
- состояние воспроизведения;
- идентификатор последней команды;
- локальное время.

Ведущий вычисляет приблизительный рассинхрон.

При небольшом расхождении коррекция не выполняется.

При большом расхождении ведущий отправляет команду коррекции позиции.

Коррекция отправляется при отклонении больше 400 мс, не чаще одного раза за 3 секунды. Эти параметры сами по себе не гарантируют плавное воспроизведение.

# Проверка видеофайлов

SyncWatch не сравнивает файлы только по имени.

Для проверки используются:

- размер файла;
- длительность видео;
- первый блок файла;
- блок из середины файла;
- последний блок файла.

Блоки объединяются и хешируются алгоритмом SHA-256.

Это позволяет быстро проверять большие видео без полного чтения всего файла.

Во время расчёта отпечатка интерфейс не должен зависать.

# Сетевые требования

Оба устройства должны находиться:

- в одной домашней Wi-Fi-сети;
- или в одной Ethernet-сети;
- или в одной локальной подсети.

Рекомендуется:

- использовать частную домашнюю сеть;
- отключить VPN;
- разрешить входящие подключения;
- не использовать гостевой Wi-Fi;
- не менять сеть во время просмотра;
- не переводить компьютеры в спящий режим.

Работа может быть невозможна:

- в гостевой Wi-Fi-сети;
- при включённой изоляции клиентов;
- в корпоративной сети;
- через VPN;
- через разные подсети;
- через мобильный интернет;
- через интернет без дополнительной настройки.

# Сборка автономной версии

Автономная сборка позволяет запускать SyncWatch без отдельной установки Python и VLC.

В готовый пакет должны входить:

- интерпретатор Python;
- PySide6;
- websockets;
- python-vlc;
- libVLC;
- плагины VLC;
- исходный код приложения.

PyInstaller не поддерживает полноценную кросс-компиляцию.

Поэтому:

- Windows-сборка создаётся на Windows;
- macOS-сборка создаётся на macOS.

---

Активируйте окружение:

```powershell
.venv\Scripts\Activate.ps1
```

```powershell
pip install pyinstaller
```

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

# Решение проблем на Windows

## Ошибка `Could not find module libvlc.dll`

Пример ошибки:

```text
FileNotFoundError: Could not find module '...\libvlc.dll'
```

Проверьте наличие:

```text
C:\Program Files\VideoLAN\VLC\libvlc.dll
```

Настройте переменные окружения:

```powershell
$env:VLC_HOME="C:\Program Files\VideoLAN\VLC"
$env:PATH="$env:VLC_HOME;$env:PATH"
$env:VLC_PLUGIN_PATH="$env:VLC_HOME\plugins"
```

Проверьте:

```powershell
python -c "import vlc; print(vlc.libvlc_get_version())"
```

---

## Ошибка `or one of its dependencies`

Это означает, что `libvlc.dll` найден, но Windows не может загрузить зависимые библиотеки.

Проверьте наличие:

```text
libvlc.dll
libvlccore.dll
plugins\
```

Не копируйте в проект только один файл `libvlc.dll`.

Используйте полную папку VLC.

---

## VLC находится в `Program Files (x86)`

Путь:

```text
C:\Program Files (x86)\VideoLAN\VLC
```

обычно означает 32-битный VLC.

Для 64-битного Python необходимо установить 64-битный VLC в:

```text
C:\Program Files\VideoLAN\VLC
```

Проверьте Python:

```powershell
python -c "import struct; print(struct.calcsize('P') * 8)"
```

Ожидаемый результат:

```text
64
```

---

## Не подключается второй компьютер

Проверьте:

- IP-адрес ведущего;
- порт;
- код комнаты;
- брандмауэр;
- наличие общей сети;
- отсутствие VPN;
- отсутствие изоляции клиентов;
- одинаковую версию приложения.

Проверить доступность ведущего можно командой:

```powershell
ping 192.168.1.100
```

Замените адрес на IP ведущего.

Некоторые устройства блокируют ping, поэтому его отсутствие не всегда означает, что WebSocket-соединение невозможно.

---

## Видео не запускается на ведомом

Убедитесь, что:

- файлы отмечены как совпадающие;
- оба устройства готовы;
- используется одинаковая версия SyncWatch;
- управление выполняется с ведущего;
- соединение не потеряно;
- файл открывается в обычном VLC.

---

Выполните:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

После этого:

```powershell
.venv\Scripts\Activate.ps1
```

# Безопасность

SyncWatch предназначен для работы в доверенной локальной сети.

Приложение:

- не отправляет видео в интернет;
- не загружает файлы на сервер;
- не требует регистрации;
- не требует учётной записи;
- не использует облачную инфраструктуру;
- пока хранит один клиентский сокет; для нескольких ведомых нужны отдельные соединения и рассылка;
- проверяет код комнаты;
- проверяет версию протокола;
- передаёт идентификатор сессии, но пока не проверяет его при чтении сообщений;
- ограничивает список поддерживаемых команд.

В MVP используется обычный WebSocket без TLS.

Не рекомендуется использовать приложение в открытых или недоверенных сетях.

# Логи

Приложение записывает локальный журнал в `~/.syncwatch/logs/syncwatch.log`. Сейчас явно логируются ошибки запуска и серверного обработчика; остальные перечисленные ниже события — возможное расширение логирования, а не гарантия текущей реализации.

В журнал могут попадать:

- запуск приложения;
- версия программы;
- операционная система;
- создание комнаты;
- подключения;
- отключения;
- сетевые ошибки;
- Play/Pause/Seek-команды;
- ping;
- рассинхронизация;
- коррекции;
- ошибки VLC;
- ошибки файлов.

В лог не должно записываться содержимое видео.
